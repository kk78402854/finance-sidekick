# 05 测试验收与风险

## 1. 测试分层

| 层级 | 目标 | 方式 |
|---|---|---|
| 接口层 | 确认 finance-data 契约 | Swagger / curl / `finance-data\tests` |
| Action 单测 | 确认参数、异常、幂等 | mock httpx，不连真实服务 |
| 流程测试 | 确认槽位、分支、结束 | 直接调用引擎，发送文本 |
| E2E | 确认完整对话与状态 | 前端或 HTTP API |
| 恢复测试 | 确认重启后可继续 | 重启服务 + 恢复会话 |

## 2. 核心用例

### 2.1 账户查询

| 用例 | 输入 | 期望 |
|---|---|---|
| 直接给账户号 | “查一下 6222... 的余额” | 不追问账户号，直接返回余额/可用/冻结 |
| 只说要查账户 | “帮我查账户余额” | 追问账户号 |
| 全部账户 | “查我所有账户” | `account_scope=all`，返回账户列表 |
| 对象消息 | 发送 `account` 对象 | 自动填 `account_no`，不追问 |
| 账户不存在 | 给一个不存在的账户号 | 返回“账户不存在或无权访问”，不抛异常 |

### 2.2 交易查询

| 用例 | 输入 | 期望 |
|---|---|---|
| 正常范围 | “查最近一周的消费记录” | 日期归一化为 ISO，返回流水摘要 |
| 无记录 | 查一个没有交易的时间段 | 返回“该时间段没有交易记录” |
| 缺账户号 | “查一下流水” | 追问账户号 |
| 对象消息 | 发送 `transaction` 对象 | 自动填 `transaction_no`，并尽可能带出 `account_no` |

### 2.3 贷款申请

| 用例 | 输入 | 期望 |
|---|---|---|
| 正常申请 | “我想申请 5 万消费贷，12 个月，装修” | 追问缺失项 → 查额度 → 提交 → 返回申请编号 |
| 额度不足 | 申请金额 > 可用额度 | 返回“额度不足”，不提交 |
| 金额超范围 | 金额低于产品起贷点 | 返回产品金额范围，不提交 |
| 期限超范围 | 期限不在产品范围 | 返回期限范围，不提交 |
| 无授信 | 客户没有有效额度 | 返回“暂无可用授信额度”，流程结束 |
| 重复提交 | 同一会话重试 | 复用 `request_no`，不产生两笔申请 |

### 2.4 信用卡挂失

| 用例 | 输入 | 期望 |
|---|---|---|
| 正常挂失 | 卡号 + 丢失 + 姓名 + 证件后四位 | 创建 `card_loss` 工单，返回工单号 |
| 缺身份信息 | 只给卡号 | 追问姓名/证件号 |
| 工单接口无员工头 | 不带 `X-Operator-No` | 返回 403，action 写 `loss_result` 错误提示 |

### 2.5 投诉工单

| 用例 | 输入 | 期望 |
|---|---|---|
| 有交易号 | “转账没到账，交易号 TX...” | 工单内容包含交易号 |
| 无交易号 | “我要投诉服务态度” | 正常创建工单，内容不含交易号 |
| 工单类型 | “我想提个建议” | `ticket_type` 为建议/consult，不强制 complaint |

### 2.6 知识检索

| 用例 | 期望 |
|---|---|
| 提前还款政策 | FAQ/RAG 返回，不编造违约金比例 |
| 贷款利率 | 返回产品区间或“以申请页面为准”，不编具体利率 |
| 理财风险 | 必须包含风险提示 |
| 检索为空 | 回答“暂时没有查到，建议转人工”，不胡编 |
| 单个 Provider 超时 | 其他 Provider 的结果仍能回答 |

### 2.7 流程管控

| 用例 | 输入 | 期望 |
|---|---|---|
| 切换 | 贷款填到一半，说“先查账户” | 贷款进入 `paused`，账户查询开始 |
| 恢复 | 账户查完，说“继续贷款” | 从停下的槽位继续，不重复问已填项 |
| 取消 | “算了，不贷了” | 贷款任务取消，状态清理 |
| 多任务 | 贷款暂停后再取消另一任务 | 只取消指定任务，不影响其他任务 |

### 2.8 持久化与恢复

| 步骤 | 期望 |
|---|---|
| 创建会话，填两个槽位 | `dialogue_states` 有 `state_json` |
| 重启客服服务 | 会话仍可读取 |
| 重新发送“继续刚才的贷款申请” | 恢复 `paused` 任务与槽位 |
| 保存失败 | 回复仍成功，日志有告警，不阻断对话 |

## 3. 演示脚本（一条连续对话）

建议按下面顺序录制，能覆盖全部验收点：

1. **知识咨询**
   - 用户：“提前还款有违约金吗？”
   - 期望：FAQ/RAG 回答，带合规提示。

2. **账户查询 + 对象消息**
   - 用户：“帮我查一下账户余额。”
   - 系统追问账户号。
   - 用户发送 `account` 对象（或输入账户号）。
   - 期望：返回余额、可用余额、冻结金额。

3. **交易查询**
   - 用户：“再查一下最近一周的消费记录。”
   - 期望：沿用账户号，日期归一化，返回流水摘要。

4. **贷款申请 + 切换 + 恢复**
   - 用户：“我想申请 5 万消费贷，12 个月，装修。”
   - 系统追问缺失项并查额度。
   - 用户：“先帮我看看账户余额。”
   - 期望：贷款任务暂停，账户查询完成。
   - 用户：“继续刚才的贷款申请。”
   - 期望：从停下的位置继续，提交成功，返回申请编号。

5. **信用卡挂失**
   - 用户：“我的信用卡丢了，卡号 6225...，姓名张三，身份证后四位 1234。”
   - 期望：创建挂失工单，返回工单号。

6. **投诉工单**
   - 用户：“我要投诉，昨天转账一直没到账，交易号 TX...。”
   - 期望：创建投诉工单，返回工单号。

7. **取消任务**
   - 用户：“算了，不贷了。”
   - 期望：贷款任务取消，其他会话状态不受影响。

8. **重启恢复**
   - 重启客服服务。
   - 用户：“继续刚才的投诉工单。”
   - 期望：恢复会话与任务状态。

## 5. 风险清单

| 风险 | 影响 | 处理 |
|---|---|---|
| 缺少 `Authorization` | 所有金融接口 401 | 统一 `finance_headers` |
| 工单缺少 `X-Operator-No` | 403 `EMPLOYEE_NOT_AVAILABLE` | 工单 action 使用 `with_operator=True` |
| `DEMO_CUSTOMER_NO` 不存在 | 全部 404 | 初始化后先查库确认 |
| 客户无授信额度 | 贷款流程走不通 | 演示前用 SQL 选一个有额度的客户 |
| `limit_no` 缺失 | 贷款提交 422/400 | 流程先查额度，失败分支不进提交 |
| `related_id` 传业务号 | 工单 404/422 | 统一 `related_type=none`，交易号写内容 |
| 没有信用卡实体 | 挂失无法查卡 | 挂失落工单，卡号只做内容 |
| Action 放子包 | 不注册，运行时报 action 不存在 | 直接放 `custom/` 一层 |
| 删除 action 文件没删 import | 启动报 `ModuleNotFoundError` | 同步清理 `builder.py` 顶部 import |
| MySQL 密码/端口不一致 | 启动失败 | 统一实例与密码 |
| 日期没归一化 | 交易查询 400 | Prompt 注入当前日期，统一 ISO |
| `request_no` 每次新生成 | 重复贷款/工单 | 写入 slots，重试复用 |
| 金额用 float | 精度问题 | 用 `Decimal`，传字符串 |
| Provider 异常 | 整轮 500 | `KnowledgeHandler` 捕获并跳过 |
| LLM 编造利率/额度 | 合规风险 | Prompt 强约束 + 只基于检索内容 |
| 身份证/卡号进日志 | 隐私风险 | 脱敏后记录 |
| 状态保存失败阻断回复 | 可用性风险 | try/except 降级 |
| SSE 超时 | 前端一直转圈 | 设置合理超时与错误事件 |
