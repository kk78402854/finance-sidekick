# 01 环境与配置

本文档把金融数据服务、客服工程和演示身份配置到“第一条链路可跑通”的状态。

---

## 1. 组件与端口

| 组件 | 默认地址 | 说明 |
|---|---|---|
| finance-data API | `http://127.0.0.1:8000` | 金融业务中台，接口前缀 `/api/v1` |
| finance-data MySQL | `127.0.0.1:3306` | 默认 `root / 123321`，库名 `finance` |
| 客服工程 API | `http://127.0.0.1:18082` | 老师代码默认端口 |
| 客服工程 MySQL 库 | `customer_service` | 保存会话状态 |

## 2. 启动 finance-data

在 `finance-data` 目录执行：

```powershell
uv sync --default-index https://pypi.tuna.tsinghua.edu.cn/simple
uv run init_db.py
uv run -m generate.main --profile full
uv run -m app.main
```

启动后验证：

- Swagger UI：`http://127.0.0.1:8000/docs`
- OpenAPI JSON：`http://127.0.0.1:8000/openapi.json`

> `generate.main --profile full` 会生成客户、账户、交易、贷款产品、授信额度、工单等数据。
> 如果只需要最小数据，可先看 `finance-data\generate\config.py` 里的 profile 定义。
>
> 注意：`init_db.py` 会先查同名库，存在就 **DROP 再重建**，然后导入 `sql/finance.sql`
> （见 `init_db.py` 的 `delete_db` / `create_db`）。库里已有数据时不要随手执行。

## 3. 统一 MySQL

finance-data 与客服工程默认密码不同：

| 工程 | 配置项 | 默认值 |
|---|---|---|
| finance-data | `DB_PASSWORD` | `123321` |
| 客服工程 | `DATABASE_URL` | `root:123456` |

两个方案二选一，**不要同时占用 3306 起两个 MySQL**。

### 方案 A：复用 finance-data 的 MySQL（推荐）

1. 使用 `finance-data\docker\docker-compose.yaml` 启动 MySQL（root 密码 `123321`）。
2. 把客服工程 `.env` 的 `DATABASE_URL` 改成：

```text
DATABASE_URL=mysql+aiomysql://root:123321@127.0.0.1:3306/customer_service?charset=utf8mb4
```

3. 在同一个 MySQL 实例里创建 `customer_service` 库，并执行客服库建表脚本。

### 方案 B：复用本机已有 MySQL

1. 本机 MySQL 密码以实际为准（例如 `123456`）。
2. 修改 `finance-data\.env`：

```text
DB_PASSWORD=123456
```

3. 重新执行 `uv run init_db.py` 和 `uv run -m generate.main --profile full`。

> 如果之前已经用 `123321` 初始化过 finance 库，改密码后旧容器里的数据不会自动迁移；
> 最省事的做法是固定一个实例，把两边配置改成一致。

## 5. 选择演示身份

金融接口的鉴权不是传统账号密码，而是：

- `Authorization: Bearer <customer_no>`：客户登录态
- `X-Channel-Code`：渠道编码，必须存在于 `dim_channel`
- `X-Operator-No`：员工编号，工单等接口需要，必须存在于 `dim_employee`

### 5.1 找演示客户
SELECT * FROM customer WHERE customer_no = 'CUS00000001';
CUS00000001'选择这个账户
优先选一个“有账户 + 有交易 + 有有效授信额度”的客户：

```sql
SELECT
    c.customer_no,
    a.account_no,
    cl.limit_no,
    cl.available_limit_amount
FROM customer c
JOIN bank_account a ON a.customer_id = c.id
JOIN credit_limit cl ON cl.customer_id = c.id AND cl.limit_status = 'active'
WHERE c.customer_status = 'active'
LIMIT 5;
```

如果没有结果，说明当前数据 profile 没有给客户生成授信额度：

- 换一个客户再查；
- 或调整 `generate` 的数据 profile 后重新生成；
- 或先只演示账户/交易/工单，贷款流程后续补数据。

> 生成数据的客户号形如 `CUS00000001`，账户号形如 `ACC...`，授信额度号形如 `CL...`。
> 状态枚举以生成数据为准（`bank_account.account_status` 用 `active`，`credit_limit.limit_status`
> 也按 `active` 判断，见 `app/routers/loans.py`）。查不到时先去掉 `customer_status` /
> `limit_status` 条件看全量，再按实际值调整。

### 5.2 找渠道和员工

```sql
SELECT channel_code
FROM dim_channel
WHERE channel_status = 'active' AND yn = 1
LIMIT 5;

SELECT employee_no
FROM dim_employee
WHERE employee_status = 'active'
LIMIT 5;
```

把结果分别填入 `FINANCE_CHANNEL_CODE`、`FINANCE_OPERATOR_NO`。

## 6. 修改客服工程配置

### 6.1 `.env`

在客服工程 `.env` 中增加：

```text
FINANCE_API_BASE_URL=http://127.0.0.1:8000
FINANCE_CHANNEL_CODE=MOBILE_BANK
FINANCE_OPERATOR_NO=EMP000001
DEMO_CUSTOMER_NO=CUS00000001
```

> 上面的值来自 `seeds/1_foundation/dim_channel.csv`、`dim_employee.csv` 的样例，
> 客户号格式是 `code("CUS", customer_id, 8)`（见 `generate/layers/layer2.py`），即 `CUS` + 8 位数字。
> 三者都必须换成当前库里真实存在且启用的值。

### 6.2 `atguigu/conf/config.py`

在 `Settings` 中增加字段（`extra='ignore'`，旧配置不受影响）：

```python
finance_api_base_url: str
finance_channel_code: str
finance_operator_no: str
demo_customer_no: str
```

如果不想改字段名，也可以继续用 `commerce_api_base_url` 只改值，但可读性差，不推荐。

## 7. 统一鉴权头

在 `atguigu/utils/httpx_client.py` 增加：

```python
import uuid

from atguigu.conf.config import settings


def finance_headers(
    customer_no: str,
    *,
    with_operator: bool = False,
) -> dict[str, str]:
    headers = {
        "Authorization": f"Bearer {customer_no}",
        "X-Channel-Code": settings.finance_channel_code,
        "X-Request-Id": str(uuid.uuid4()),
    }
    if with_operator:
        headers["X-Operator-No"] = settings.finance_operator_no
    return headers
```

约定：

- 客户侧接口（账户、交易、贷款申请）：`with_operator=False`。
- 工单接口：`with_operator=True`。因为 `create_support_ticket` 内部会调用 `current_employee(ctx)`，
  没有有效员工编号会返回 `403 EMPLOYEE_NOT_AVAILABLE`。
- 写接口另有 `request_no` 做幂等，和 `X-Request-Id` 不是一回事。

## 8. 连通性自检

### 8.1 查账户列表

```powershell
$h = @{
  Authorization      = "Bearer <DEMO_CUSTOMER_NO>"
  "X-Channel-Code"   = "<CHANNEL_CODE>"
  "X-Request-Id"     = [guid]::NewGuid().ToString()
}
Invoke-RestMethod `
  -Uri "http://127.0.0.1:8000/api/v1/customers/<DEMO_CUSTOMER_NO>/accounts" `
  -Headers $h
```

期望返回：

```json
{
  "code": 0,
  "message": "ok",
  "request_id": "...",
  "data": {
    "list": [
      {
        "account_no": "...",
        "balance_amount": "...",
        "currency_code": "CNY",
        "account_product": { "product_code": "...", "product_name": "..." }
      }
    ]
  }
}
```

### 8.2 查授信额度

```powershell
Invoke-RestMethod `
  -Uri "http://127.0.0.1:8000/api/v1/customers/<DEMO_CUSTOMER_NO>/credit-limits" `
  -Headers $h
```

期望 `data.list` 中至少有 `limit_no`、`available_limit_amount`、`product_code`。

> 注意：这个接口返回该客户名下**全部**额度，不返回 `limit_status`。
> 有多条时优先选 `available_limit_amount` 最大的一条；额度是否可用，
> 由 `POST /loan/applications` 内部校验 `limit_status == 'active'` 决定。

### 8.3 创建工单

```powershell
$h["X-Operator-No"] = "<EMPLOYEE_NO>"

$body = @{
  request_no   = [guid]::NewGuid().ToString()
  customer_no  = "<DEMO_CUSTOMER_NO>"
  ticket_type  = "complaint"
  ticket_title = "转账未到账"
  ticket_content = "交易号 TX...，转账一直未到账"
  related_type = "none"
} | ConvertTo-Json

Invoke-RestMethod `
  -Uri "http://127.0.0.1:8000/api/v1/support/tickets" `
  -Method Post -Headers $h -ContentType "application/json" -Body $body
```

期望返回 `data.ticket_no`。

## 9. 常见错误对照

| 错误 | 原因 | 处理 |
|---|---|---|
| `401 MISSING_AUTHORIZATION` / `401 MISSING_HEADER` | 缺 `Authorization` 或 `X-Channel-Code` | 两个头都带上 |
| `401 INVALID_AUTHORIZATION` | 不是 `Bearer ` 前缀 | 使用 `Bearer <customer_no>` |
| `401 PRINCIPAL_NOT_FOUND` | token 既不是客户号也不是员工号 | 用库里真实的 `customer_no` |
| `403 CUSTOMER_SCOPE_FORBIDDEN` | 请求体客户号与登录客户号不一致 | 演示阶段固定同一个客户 |
| `403 EMPLOYEE_NOT_AVAILABLE` | 工单接口没有有效 `X-Operator-No` | 从 `dim_employee` 取真实员工编号 |
| `403 CHANNEL_NOT_AVAILABLE` | `X-Channel-Code` 不存在或未启用 | 从 `dim_channel` 取真实渠道 |
| `404 CUSTOMER_NOT_FOUND` | `DEMO_CUSTOMER_NO` 不在库里 | 重新查客户号 |
| `409 CREDIT_LIMIT_NOT_ENOUGH` | 申请金额超过可用额度 | 降低金额或换客户 |
| `409 CREDIT_LIMIT_STATUS_FORBIDDEN` | 额度不是 `active` | 换一条有效额度 |
| `400 LOAN_AMOUNT_OUT_OF_RANGE` | 金额不在产品区间 | 用产品详情的 `min_amount/max_amount` |
| `400 LOAN_TERM_OUT_OF_RANGE` | 期限不在产品区间 | 用产品详情的 `min/max_term_months` |
| `404 ACCOUNT_NOT_FOUND` | 账户号不存在 | 用客户账户列表接口先查 |
| `Access denied for user 'root'` | MySQL 密码不一致 | 统一 `.env` 中的密码 |
| `Can't connect to MySQL server` | 端口冲突或容器没启动 | 只保留一个 3306 实例 |

> 失败响应的 `code` 是**字符串**（如 `ACCOUNT_NOT_FOUND`），只有成功时 `code` 才是数字 `0`，
> 判断逻辑要写成 `resp.status_code >= 400 or payload.get("code") != 0`。
