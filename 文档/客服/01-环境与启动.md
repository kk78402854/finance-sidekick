# 01 环境与启动

## 1. 运行环境

| 项 | 要求 |
| --- | --- |
| Python | 3.12+（`pyproject.toml` 的 `requires-python`） |
| MySQL | 8.0+，本服务使用 `finance_assistant` 库 |
| 大模型 | OpenAI 兼容接口（默认 DashScope `qwen-flash`） |
| 金融中台 | `finance-data` 已启动，默认 `http://127.0.0.1:8000` |

依赖全部在 `pyproject.toml`：fastapi、uvicorn、httpx、aiomysql、sqlalchemy、pydantic-settings、pyyaml、jinja2、langchain、langchain-openai、cryptography。

安装：

```bash
cd finance-assistant
uv sync                 # 使用 uv
# 或
pip install -e .
```

## 2. 数据库

表由服务启动时自动创建（`assistant/utils/db.py` 的 `create_tables`），只需要先建库：

```sql
CREATE DATABASE IF NOT EXISTS finance_assistant DEFAULT CHARSET utf8mb4;
```

启动后会自动出现两张表：

| 表 | 用途 |
| --- | --- |
| `dialogue_states` | 按 `sender_id` 保存完整对话状态 JSON |
| `faq_items` | 知识检索用的 FAQ，初始为空，按 04 文档写入数据 |

## 3. `.env` 配置

`.env` 必须放在项目根目录（`conf/config.py` 用 `Path(__file__).parents[2] / '.env'` 定位）。

```ini
LLM_MODEL=qwen-flash
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=sk-xxxx

FINANCE_API_BASE_URL=http://127.0.0.1:8000
FINANCE_CHANNEL_CODE=MOBILE_BANK
FINANCE_OPERATOR_NO=EMP000001
DEMO_CUSTOMER_NO=CUS00000001
FINANCE_RAG_BASE_URL=

DATABASE_URL=mysql+aiomysql://root:123321@127.0.0.1:3306/finance_assistant?charset=utf8mb4

APP_HOST=0.0.0.0
APP_PORT=18083
```

| 变量 | 说明 |
| --- | --- |
| `LLM_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY` | 意图识别与回复润色使用的大模型 |
| `FINANCE_API_BASE_URL` | 金融中台地址，代码会自动拼 `/api/v1` |
| `FINANCE_CHANNEL_CODE` | 渠道编码，作为 `X-Channel-Code` 发送。必须是 `dim_channel` 中存在且启用的值，否则金融接口返回 `403 CHANNEL_NOT_AVAILABLE` |
| `FINANCE_OPERATOR_NO` | 员工编号，工单接口作为 `X-Operator-No` 发送。必须是 `dim_employee` 中存在且启用的值，否则返回 `403 EMPLOYEE_NOT_AVAILABLE` |
| `DEMO_CUSTOMER_NO` | 演示客户号。当前没有登录体系，所有请求都以该客户身份发起，同时作为 `Authorization: Bearer <customer_no>` |
| `FINANCE_RAG_BASE_URL` | 外部知识库检索地址，留空则跳过 RAG |
| `DATABASE_URL` | 本服务自己的库，和金融中台的库相互独立 |
| `APP_HOST` / `APP_PORT` | 客服服务监听地址，默认 18083 |

> 两个 403 是联调最常见的错误：`FINANCE_CHANNEL_CODE`、`FINANCE_OPERATOR_NO` 必须从金融中台库里取真实存在的值：
>
> ```sql
> SELECT channel_code FROM dim_channel WHERE channel_status='active' AND yn=1 LIMIT 5;
> SELECT employee_no FROM dim_employee WHERE employee_status='active' LIMIT 5;
> ```

## 4. 启动顺序

```bash
# 1) 先启动金融中台（仓库 finance-data）
cd finance-data
uvicorn app.main:app --host 0.0.0.0 --port 8000

# 2) 再启动客服助手
cd finance-assistant
python main.py
```

启动入口是根目录 `main.py`：

1. `init_dialogue_engine()`：加载 `flow_config/user_flows.yml`、注册 6 个 Action、装配 7 个知识 Provider；
2. `uvicorn` 拉起 `assistant.api.app:app`；
3. FastAPI `lifespan` 中依次执行：创建数据库引擎 → 建表 → 创建 HTTP 客户端；关闭时释放连接。

> 请用 `python main.py` 启动。直接执行 `uvicorn assistant.api.app:app` 会跳过 `init_dialogue_engine()`，请求时报对话引擎未初始化。

启动成功的判断：

- 控制台输出 `Uvicorn running on http://0.0.0.0:18083`；
- 访问 `http://127.0.0.1:18083/docs` 能看到 `/api/chat`、`/api/chat/history`；
- 如果 MySQL 未启动，会在启动阶段直接抛连接错误，此时先修数据库而不是改代码。

## 5. 对外接口

### 5.1 发送消息 `POST /api/chat`

请求字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sender_id` | string | 是 | 用户标识，同时是会话状态主键 |
| `text` | string | 否 | 文本消息；与 `object` 二选一 |
| `object` | object | 否 | 对象消息，见 03 文档 |
| `message_id` | string | 否 | 不传则服务端生成 UUID |

文本请求：

```bash
curl -X POST http://127.0.0.1:18083/api/chat \
  -H "Content-Type: application/json" \
  -d '{"sender_id":"u1001","text":"帮我查一下我的账户余额"}'
```

对象消息请求（用户点了账户卡片）：

```bash
curl -X POST http://127.0.0.1:18083/api/chat \
  -H "Content-Type: application/json" \
  -d '{
    "sender_id": "u1001",
    "object": {
      "type": "account",
      "id": "6222020200000001",
      "title": "储蓄卡",
      "attributes": {}
    }
  }'
```

响应：

```json
{
  "sender_id": "u1001",
  "message_id": "9f0c...",
  "messages": [
    {"text": "你好，这里是金融智能助手。我可以帮你查询账户和交易……", "object": null}
  ]
}
```

`messages` 是列表，一轮可能返回多条（例如先说明再给结果）。

### 5.2 查询历史 `GET /api/chat/history`

```bash
curl "http://127.0.0.1:18083/api/chat/history?sender_id=u1001"
```

返回该用户全部会话中的所有轮次，`role` 为 `user` 或 `bot`。

## 6. 与金融中台的约定

- 每个请求自动带 `Authorization: Bearer <DEMO_CUSTOMER_NO>`、`X-Channel-Code`、`X-Request-Id`；工单类额外带 `X-Operator-No`。
- 金融中台成功时 `code=0`，失败时 `code` 是字符串错误码且 HTTP 为 4xx。
- `assistant/utils/finance_client.py` 把常见错误码翻译成中文提示，未知错误回落到接口 `message`。
- 金额统一用 `Decimal` 处理并格式化为千分位两位小数，避免浮点误差。
