```bash
cd finance-assistant
```

期望：

- 编译无输出；

- flow 列表为 `onboarding, account_query, transaction_query, loan_application, card_loss, complaint_ticket, human_handoff`。

## 4. 异常与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 金融接口 403 `CHANNEL_NOT_AVAILABLE` | `FINANCE_CHANNEL_CODE` 不在 `dim_channel` 或未启用 | 按第 2 节查到有效渠道并改 `.env`，重启 |
| 金融接口 403 `EMPLOYEE_NOT_AVAILABLE` | `FINANCE_OPERATOR_NO` 无效 | 换 `dim_employee` 中的有效员工号 |
| 404 `ACCOUNT_NOT_FOUND` | 账户号不属于当前客户或不存在 | 用 `fact_account` 里属于 `DEMO_CUSTOMER_NO` 的账户 |
| 启动时报 MySQL 连接错误 | 库不存在、账号密码错、服务未启动 | 建 `finance_assistant` 库，核对 `DATABASE_URL` |
| 启动时报 `dialogue engine` 未初始化 | 用 `uvicorn assistant.api.app:app` 启动 | 改用 `python main.py` |
| 大模型 401 / 超时 | `LLM_API_KEY` 无效或网络不通 | 更换 key；确认能访问 `LLM_BASE_URL` |
| 端口占用 | 18083 被占用 | 改 `.env` 的 `APP_PORT` |
| 流程停在某一步不推进 | 该步 `next` 只有 1 个条件分支，条件不成立时取不到目标 | 按 02 文档改成 `if` + `else` 成对 |
| 回复为空/模板变量没渲染 | Action 没写对应槽位 | 检查 Action 的 `slots_update` 键名与模板一致 |
| 知识问题答非所问 | 意图识别偏差 | 调整 `turn_plan.jinja2` 的示例或 `intents.py` 的描述 |
| FAQ 永远查不到 | `faq_items` 为空 | 按 04 文档插入数据 |
| 同一请求重复建单 | 未复用 `request_no` | 确认 Action 使用 `new_request_no(slots)`，不要每次新生成 |

## 5. 验收标准

- [ ] 6 个流程都能从入口走到 `end`，中途取消、切换任务不报错；
- [ ] 所有写接口（贷款、挂失、投诉）在接口失败时给中文原因，不抛 500；
- [ ] 金额、日期展示正确，无浮点尾差；
- [ ] 对象消息能填槽，不需要用户重复输入卡号/账户号；
- [ ] 知识问答不编造利率、额度、政策；
- [ ] 会话历史接口能查到多轮记录；
- [ ] 金融中台不可用时，客服仍能返回可读的错误提示。
