# 02 流程与槽位

对应文件：`customer_service老师代码\flow_config\user_flows.yml`

---

## 1. 设计原则

1. **客户身份不作为槽位反复追问**：`customer_no` 来自登录态（演示阶段用 `DEMO_CUSTOMER_NO`），
   只有账户号、卡号、交易号等业务标识才需要收集。
2. **必填才 collect，可选靠 LLM 预填**：例如投诉的交易号可以没有，就不做 `collect` 步骤，
   用户提到了就由 `set_slots` 自动进槽位。
3. **action 只读槽位、只写结果**：action 不负责追问，缺参数时写 `error_message` 并返回。
4. **流程切换/恢复/取消复用骨架**：`start_flow` 会把当前任务移到 `paused`，
   `resume_task` / `cancel_task` 由命令处理器处理，YAML 不需要额外配置。

---

## 2. 槽位定义

用下面的内容替换 `user_flows.yml` 顶层的 `slots:`。

```yaml
slots:
  # ---------- 业务标识 ----------
  account_no:
    type: text
    label: 账户号
    description: 要查询的银行账户号；用户想查全部账户时可为空

  account_scope:
    type: text
    label: 账户范围
    description: 取值为 all 时表示查询当前客户的全部账户

  card_no:
    type: text
    label: 银行卡号
    description: 业务对象消息里的银行卡号，可从 attributes.account_no 关联账户

  credit_card_no:
    type: text
    label: 信用卡号
    description: 需要挂失的信用卡号

  transaction_no:
    type: text
    label: 交易号
    description: 当前咨询或投诉关联的交易流水号

  loan_type:
    type: text
    label: 贷款类型
    description: 用户口语里的贷款类型；action 内映射成接口枚举 consumer/cash/installment/business

  loan_amount:
    type: number
    label: 贷款金额
    description: 申请贷款的金额，单位元

  loan_term_months:
    type: number
    label: 贷款期限
    description: 贷款期限，单位月

  loan_purpose:
    type: text
    label: 贷款用途
    description: 申请贷款的资金用途

  repayment_method:
    type: text
    label: 还款方式
    description: 接口枚举 equal_principal_interest/equal_principal/interest_first，由贷款产品详情写入

  loss_reason:
    type: text
    label: 挂失原因
    description: 信用卡丢失、被盗刷等

  identity_name:
    type: text
    label: 姓名
    description: 用于挂失工单的身份信息

  identity_id_no:
    type: text
    label: 证件号
    description: 身份证号或后四位，演示阶段只做必填校验

  ticket_type:
    type: text
    label: 工单类型
    description: complaint、card_loss、consult 等

  problem_desc:
    type: text
    label: 问题描述
    description: 用户投诉或咨询的具体问题

  related_transaction_no:
    type: text
    label: 关联交易号
    description: 投诉关联的交易流水号，可为空

  # ---------- 查询/办理结果（只由 action 写入） ----------
  account_summary:
    type: text
    label: 账户摘要
    description: 账户查询结果的展示文本

  balance_amount:
    type: text
    label: 账户余额
    description: 账户当前余额

  available_amount:
    type: text
    label: 可用余额
    description: 余额减去冻结金额

  frozen_amount:
    type: text
    label: 冻结金额
    description: 账户冻结金额

  transaction_summary:
    type: text
    label: 交易摘要
    description: 交易流水查询结果的展示文本

  transaction_start_date:
    type: text
    label: 开始日期
    description: 交易查询开始日期，ISO 格式 yyyy-MM-dd

  transaction_end_date:
    type: text
    label: 结束日期
    description: 交易查询结束日期，ISO 格式 yyyy-MM-dd

  credit_limit_summary:
    type: text
    label: 授信摘要
    description: 可用授信额度说明

  limit_no:
    type: text
    label: 授信额度编号
    description: 贷款申请必填

  product_code:
    type: text
    label: 贷款产品编码
    description: 根据贷款类型匹配到的产品编码

  loan_result:
    type: text
    label: 贷款申请结果
    description: 成功时包含申请编号，失败时包含原因

  loan_application_no:
    type: text
    label: 贷款申请编号
    description: 提交贷款申请后返回的编号

  ticket_no:
    type: text
    label: 工单号
    description: 创建工单后返回的编号

  ticket_result:
    type: text
    label: 工单结果
    description: 工单创建结果的展示文本

  loss_result:
    type: text
    label: 挂失结果
    description: 挂失工单创建结果的展示文本

  error_message:
    type: text
    label: 错误信息
    description: action 调用失败时的错误说明
```

### 2.1 口语 → 接口枚举（必须做）

`finance-data` 的 `loan_product` 表用英文枚举，YAML 和 Prompt 面向用户仍然用中文，
转换必须放在 action 里，不要让 LLM 直接产出英文枚举以外的值：

| 用户说法 | `loan_type` | 说明 |
|---|---|---|
| 消费贷、信用贷、装修、教育 | `consumer` | 标准/优享/薪享/绿色消费贷 |
| 现金贷、周转 | `cash` | 极速/小额/工资客户现金贷 |
| 分期贷、车贷、家装、教育分期 | `installment` | 大额/汽车/家装/教育分期贷 |
| 经营贷、企业贷、税票贷、供应链 | `business` | 小微/税票/商户/供应链/抵押经营贷 |

`repayment_method` 同样用英文枚举：

| 接口值 | 展示话术 |
|---|---|
| `equal_principal_interest` | 等额本息 |
| `equal_principal` | 等额本金 |
| `interest_first` | 先息后本 |

> 产品详情接口返回的就是英文枚举，展示给用户前用上表反查中文，
> 提交贷款申请时原样回传英文值。

## 3. Flow 清单

| flow_id | 名称 | 必收集槽位 | action |
|---|---|---|---|
| `onboarding` | 欢迎引导 | 无 | 无 |
| `account_query` | 账户查询 | `account_no`（或 `account_scope=all`） | `action_query_account` |
| `transaction_query` | 交易查询 | `account_no`、`transaction_start_date`、`transaction_end_date` | `action_query_transactions` |
| `loan_application` | 贷款申请 | `loan_type`、`loan_amount`、`loan_term_months`、`loan_purpose` | `action_query_credit_limit` → `action_submit_loan_application` |
| `card_loss` | 信用卡挂失 | `credit_card_no`、`loss_reason`、`identity_name`、`identity_id_no` | `action_report_card_loss` |
| `complaint_ticket` | 投诉工单 | `ticket_type`、`problem_desc` | `action_create_complaint_ticket` |
| `human_handoff` | 人工客服 | 无 | 无 |

## 5. 流程切换 / 恢复 / 取消

这部分**不需要改 YAML**，依赖骨架已有命令：

| 命令 | 行为 |
|---|---|
| `start_flow` | 当前 active 任务移到 `paused`，新建任务并激活 |
| `resume_task` | 从 `paused` 恢复指定任务，当前任务移到 `paused` |
| `cancel_task` | 取消指定任务，清空其状态 |

演示脚本：

1. 用户开始 `loan_application`，填到“贷款金额”时停下。
2. 用户说“先帮我查一下账户余额” → `start_flow account_query`，贷款任务进入 `paused`。
3. 账户查询结束后，用户说“继续刚才的贷款申请” → `resume_task`，从“贷款金额”继续。
4. 用户说“算了，不申请了” → `cancel_task`，贷款任务结束。

只要每个 flow 的 `start → collect → action → response → end` 完整，切换和恢复就能工作。

## 6. 对象消息预填槽位

用户在聊天窗口发送业务对象（账户、银行卡、交易、贷款）时，`collect` 步骤会尝试从
`state.shared.focused_object` 自动填槽：

| 对象 `type` | 可填槽位 |
|---|---|
| `account` | `account_no` |
| `card` | `account_no` |
| `credit_card` | `credit_card_no` |
| `transaction` | `transaction_no` / `related_transaction_no` |
| `loan` | `loan_application_no` |

对应代码改动见 [03-Action与对象消息](03-Action与对象消息.md)。

## 7. 常见设计问题

### 7.1 为什么 `customer_no` 不做 collect？

因为它是登录身份，不是用户在对话里需要反复提供的业务参数。
action 从配置或会话上下文取 `customer_no`，请求体与 `Authorization` 保持一致。

### 7.2 为什么投诉的交易号不做 collect？

交易号是可选信息。做成 `collect` 会强制用户提供，体验差。
在 Prompt 里约定：用户提到交易号就 `set_slots`，没提到就留空，action 用
`related_type=none` 创建工单，把交易号写进工单内容。

### 7.3 为什么贷款不收集还款方式？

`repayment_method` 由贷款产品详情决定，`action_query_credit_limit` 查询产品后自动写入，
不需要让用户选。这样少一轮追问，也避免用户选到产品不支持的方式。

注意产品详情返回的是英文枚举（见 2.1），展示时再转中文。

### 7.4 条件 `next` 必须写全 if / else

`FlowStep._get_next_value` 里有一个捷径：`next` 只有 1 个元素时直接返回它的 `target`，
**不会判断条件**。所以像下面这样只写 `if` 是无效的：

```yaml
next:
  - if: "slots.get('limit_no')"
    then: submit_application
```

必须补 `else`，让它变成两个元素：

```yaml
next:
  - if: "slots.get('limit_no')"
    then: submit_application
  - else: show_loan_result
```
