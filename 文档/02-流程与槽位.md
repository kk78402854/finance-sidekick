# 02 流程与槽位

`finance-assistant/flow_config/user_flows.yml` 同时描述两件事：全局槽位（`slots`）和业务流程（`flows`）。加载后由 `assistant/task/flow/loader.py` 转成 `FlowCatalog`，执行由 `assistant/task/flowexecutor/flow_executor.py` 完成。**改流程只改 YAML，不改代码。**

---

## 1. YAML 结构

```yaml
slots:
  account_no:            # 槽位名，代码里通过 slots['account_no'] 访问
    type: text           # text / number
    label: 账户号          # 给运营看的中文名
    description: 要查询的银行账户号

flows:
  account_query:         # flow_id，LLM 只能从这里选
    name: 账户查询
    description: 查询账户余额、可用余额和冻结金额
    steps:
      - id: start        # 同一 flow 内唯一
        type: start
        next: ask_account_no
```

### 1.1 步骤类型

| type | 作用 | 关键字段 |
| --- | --- | --- |
| `start` | 流程入口，不做业务处理，直接推进 | `next` |
| `collect` | 收集槽位；槽位已有值就跳过，没有就发提示并暂停 | `slot_name`、`template.text` |
| `action` | 调用 Action 取数或写数，结果写入槽位 | `action`（必须与 Action 的 `name` 一致） |
| `response` | 用 jinja2 渲染回复，可引用 `slots.xxx` | `template.text` |
| `end` | 结束流程，清空 active 任务 | `next: []` |

> `response` 的模板只拿得到 `slots`，所以 Action 必须先把要展示的文本写进槽位（例如 `account_summary`），模板只做 `{{ slots.account_summary }}`。

### 1.2 跳转规则（重要）

```yaml
# 单元素 next：不判断条件，直接跳
next: ask_account_no

# 条件跳转：if 和 else 必须成对出现，否则会被当成无条件跳转
next:
  - if: "slots.get('limit_no')"
    then: submit_application
  - else: show_loan_result
```

- `next` 只有 1 个元素时，执行器只看 `target`，**不会 eval 条件**（`FlowStep._get_next_value` 的捷径）。需要分支时一定写 2 个及以上元素。
- 条件表达式在 `{"slots": ...}` 作用域里 eval，只能用 `slots`。
- 条件不成立且没有 `else` 时，`next` 取不到值，**流程会卡住**。

### 1.3 槽位取值优先级

`collect` 步骤的判断顺序：

1. 任务已有槽位（用户上一轮回答，或 LLM 一次性 `set_slots` 写入）；
2. 当前聚焦对象（`FocusedObject`）能映射出的值，见 [03](03-Action与对象消息.md)；
3. 都没有 → 渲染 `template.text` 追问，流程停在本步。

所以「一句话把多个槽位说全」是支持的：LLM 会输出一条 `start_flow` + 一条包含多个字段的 `set_slots`，执行时 collect 依次跳过。

## 2. 槽位清单

### 2.1 业务标识（用户 / LLM 可写）

| 槽位 | 类型 | 说明 |
| --- | --- | --- |
| `account_no` | text | 账户号；查全部账户时可为空 |
| `account_scope` | text | 值为 `all` 时查客户全部账户 |
| `card_no` | text | 银行卡号，可由对象消息 `card` 写入 |
| `credit_card_no` | text | 挂失用信用卡号 |
| `transaction_no` | text | 交易号，可由对象消息 `transaction` 写入 |
| `loan_type` | text | 用户口语的贷款类型，Action 内映射枚举 |
| `loan_amount` | number | 贷款金额（元） |
| `loan_term_months` | number | 贷款期限（月） |
| `loan_purpose` | text | 贷款用途 |
| `repayment_method` | text | 还款方式，**由产品详情写入**，用户不需要说 |
| `loss_reason` | text | 挂失原因 |
| `identity_name` | text | 持卡人姓名 |
| `identity_id_no` | text | 证件号（演示阶段只校验非空） |
| `ticket_type` | text | complaint / consult / suggestion / praise 或中文 |
| `problem_desc` | text | 问题描述 |
| `related_transaction_no` | text | 投诉关联交易号，可为空 |

### 2.2 结果槽位（只由 Action 写入）

`account_summary`、`balance_amount`、`available_amount`、`frozen_amount`、`transaction_summary`、`transaction_start_date`、`transaction_end_date`、`credit_limit_summary`、`limit_no`、`product_code`、`loan_result`、`loan_application_no`、`ticket_no`、`ticket_result`、`loss_result`、`error_message`。

> LLM 的 Prompt 明确禁止编造这些槽位；它们只能来自接口返回。

### 2.3 口语 → 接口枚举（必须做）

中台 `loan_product` 表用英文枚举，YAML 和 Prompt 面向用户仍用中文，转换放在 Action 里，不要让 LLM 直接产出枚举：

| 用户说法 | `loan_type` | 说明 |
| --- | --- | --- |
| 消费贷、信用贷、装修、教育 | `consumer` | 标准/优享/薪享/绿色消费贷 |
| 现金贷、周转 | `cash` | 极速/小额/工资客户现金贷 |
| 分期贷、车贷、家装、教育分期 | `installment` | 大额/汽车/家装/教育分期贷 |
| 经营贷、企业贷、税票贷、供应链 | `business` | 小微/税票/商户/供应链/抵押经营贷 |

`repayment_method` 同样是英文枚举，展示前反查中文：

| 接口值 | 展示话术 |
| --- | --- |
| `equal_principal_interest` | 等额本息 |
| `equal_principal` | 等额本金 |
| `interest_first` | 先息后本 |

## 3. 流程明细

7 条流程：`onboarding`、`account_query`、`transaction_query`、`loan_application`、`card_loss`、`complaint_ticket`、`human_handoff`。

### 3.1 onboarding 欢迎引导

系统主动触发。回复固定欢迎语，介绍账户、交易、贷款、挂失、工单和知识问答能力。

### 3.2 account_query 账户查询

| 步骤 | 类型 | 说明 |
| --- | --- | --- |
| start | start | 已有 `account_no` 或 `account_scope=all` → `query_account`，否则追问账户号 |
| ask_account_no | collect | 提示可以提供账户号，或说“查我全部账户” |
| query_account | action | `action_query_account` |
| show_account | response | `{{ slots.account_summary }}` |
| end | end | 结束 |

单账户返回余额、可用余额（余额−冻结）、冻结金额、状态；全部账户返回列表前 10 个。

### 3.3 transaction_query 交易查询

| 步骤 | 类型 | 说明 |
| --- | --- | --- |
| start | start | 有 `account_no` 直接问开始日期，否则先问账户 |
| ask_account_no | collect | 账户号 |
| ask_start_date | collect | 开始日期，提示 ISO 格式 |
| ask_end_date | collect | 结束日期 |
| query_transactions | action | `action_query_transactions` |
| show_transactions | response | `{{ slots.transaction_summary }}` |
| end | end | 结束 |

- 日期为空时兜底：开始日期取 30 天前，结束日期取今天。
- 单次最多取 20 条，展示前 10 条，并提示总笔数。
- 交易类型/状态是英文枚举，Action 里已映射成中文（转账、消费、存款、取现、退款、调账；成功、失败、处理中）。

### 3.4 loan_application 贷款申请

| 步骤 | 类型 | 说明 |
| --- | --- | --- |
| start | start | 进入 |
| ask_loan_type | collect | 贷款类型 |
| ask_loan_amount | collect | 金额（元） |
| ask_loan_term | collect | 期限（月） |
| ask_loan_purpose | collect | 用途 |
| query_credit_limit | action | `action_query_credit_limit`，校验额度、金额、期限、产品类型 |
| submit_application | action | 条件满足时 `action_submit_loan_application` |
| show_loan_result | response | `{{ slots.loan_result }}` |
| end | end | 结束 |

关键行为：

- 额度按可用额度最大的那条取，产品由额度上的 `product_code` 决定，不按用户说的类型随便挑产品。
- 用户想办的贷款类型与额度产品不一致时，直接告知“当前额度对应 X 产品”，不强行提交。
- 金额超出 `[min_amount, max_amount]`、期限超出 `[min_term_months, max_term_months]`、金额大于可用额度，都会在提交前拦下。
- 提交使用槽位里的 `request_no` 做幂等，重试不会重复建单。

### 3.5 card_loss 信用卡挂失

| 步骤 | 类型 | 说明 |
| --- | --- | --- |
| start | start | 已有 `credit_card_no` 跳过卡号追问 |
| ask_card_no | collect | 信用卡号 |
| ask_loss_reason | collect | 挂失原因 |
| ask_identity_name | collect | 持卡人姓名 |
| ask_identity_id | collect | 证件号后四位 |
| report_loss | action | `action_report_card_loss`，创建 `card_loss` 工单 |
| show_loss_result | response | `{{ slots.loss_result }}` |
| end | end | 结束 |

卡号与证件号写入工单前会脱敏，只保留后四位。

### 3.6 complaint_ticket 投诉工单

| 步骤 | 类型 | 说明 |
| --- | --- | --- |
| start | start | 进入 |
| ask_ticket_type | collect | 工单类型 |
| ask_problem_desc | collect | 问题描述 |
| create_ticket | action | `action_create_complaint_ticket` |
| show_ticket_result | response | `{{ slots.ticket_result }}` |
| end | end | 结束 |

`related_type` 固定 `none`；用户给的交易号写进工单正文，不作为 `related_id`（接口要求的是数据库主键）。

### 3.7 human_handoff 转人工

固定回复“好的，我来为你转接人工客服，请稍等。”，流程结束。

## 4. 流程切换 / 恢复 / 取消

这部分**不需要改 YAML**，由命令处理器使用任务栈实现：

| 命令 | 行为 |
| --- | --- |
| `start_flow` | 当前 active 任务移到 `paused`，新建任务并激活 |
| `resume_task` | 从 `paused` 恢复指定任务，当前任务移到 `paused` |
| `cancel_task` | 取消指定任务，清空其状态 |

演示脚本：

1. 用户开始 `loan_application`，填到“贷款金额”时停下；
2. 用户说“先帮我查一下账户余额” → `start_flow account_query`，贷款任务进入 `paused`；
3. 账户查询结束后，用户说“继续刚才的贷款申请” → `resume_task`，从“贷款金额”继续；
4. 用户说“算了，不申请了” → `cancel_task`，贷款任务结束。

只要每个 flow 的 `start → collect → action → response → end` 完整，切换和恢复就能工作。

## 5. 对象消息预填槽位

用户在聊天窗口发送业务对象（账户、银行卡、交易、贷款）时，`collect` 步骤会尝试从 `state.shared.focused_object` 自动填槽：

| 对象 `type` | `id` 含义 | 可填槽位 | 额外规则 |
| --- | --- | --- | --- |
| `account` | 账户号 | `account_no` | — |
| `card` | 银行卡号 | `card_no`、`account_no` | `account_no` 取 `attributes.account_no` |
| `credit_card` | 信用卡号 | `credit_card_no` | — |
| `transaction` | 交易号 | `transaction_no`、`related_transaction_no`、`account_no` | 账户号取 `attributes.account_no` |
| `loan` | 贷款申请号 | `loan_application_no` | — |

映射代码在 `assistant/domain/object_slots.py`，处理流程与典型交互见 [03-Action与对象消息](03-Action与对象消息.md)。

## 6. 新增流程的检查清单

1. 需要的槽位是否已在 `slots` 里声明？`collect` 引用了未声明的槽位不会报错，但管理上会失控。
2. `next` 里出现条件时，是否写了 `else`？
3. `action` 名是否与 `assistant/task/action/custom/*.py` 里类的 `name` 完全一致？
4. Action 是否把展示文本写进槽位，`response` 只引用槽位？
5. 修改 YAML 后执行一次自检：

```bash
python -c "from pathlib import Path; from assistant.task.flow.loader import FlowLoader; print(list(FlowLoader().load(Path('flow_config/user_flows.yml')).flows))"
```

## 7. 常见设计问题

### 7.1 为什么 `customer_no` 不做 collect？

因为它是登录身份，不是用户在对话里需要反复提供的业务参数。它来自会话状态（`state.shared.customer_no`，默认 `DEMO_CUSTOMER_NO`），Action 调接口时同时用于 `Authorization` 与请求体。

### 7.2 为什么投诉的交易号不做 collect？

交易号是可选信息，做成 `collect` 会强制用户提供。Prompt 里约定：用户提到就 `set_slots`，没提到就留空，Action 用 `related_type=none` 创建工单，把交易号写进工单内容。

### 7.3 为什么贷款不收集还款方式？

`repayment_method` 由贷款产品详情决定，`action_query_credit_limit` 查询产品后自动写入，不需要让用户选。少一轮追问，也避免用户选到产品不支持的方式。

### 7.4 只有 1 个条件分支为什么不行？

见 1.2：`next` 只有 1 个元素时执行器直接取 `target`，不 eval 条件。只写 `if` 的分支永远会走到 `then`，表现为「无条件跳转」。
