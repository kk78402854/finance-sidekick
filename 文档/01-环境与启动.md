# 01 环境与启动

把金融中台、客服工程和演示身份配置到「第一条链路可跑通」的状态。

对应目录：`finance-data/`（中台）与 `finance-data/finance-assistant/`（客服）。

---

## 1. 组件与端口

| 组件 | 默认地址 | 说明 |
| --- | --- | --- |
| 金融中台 finance-data | `http://127.0.0.1:8000` | 接口前缀 `/api/v1`，Swagger `/docs` |
| 客服 finance-assistant | `http://127.0.0.1:18083` | 网页 `/`，接口 `/api/chat` |
| MySQL | `127.0.0.1:3306`（本地）/ `3307`（Docker 映射） | 库：`finance`（中台）、`finance_assistant`（客服） |

环境要求：

| 项 | 要求 |
| --- | --- |
| Python | 3.12+（两边 `pyproject.toml` 的 `requires-python`） |
| MySQL | 8.0+ |
| 大模型 | OpenAI 兼容接口（默认 DashScope `qwen-flash`） |
| 工具 | [uv](https://docs.astral.sh/uv/)（或 pip） |

客服依赖全部在 `finance-assistant/pyproject.toml`：fastapi、uvicorn、httpx、aiomysql、sqlalchemy、pydantic-settings、pyyaml、jinja2、langchain、langchain-openai、cryptography。

## 2. 启动金融中台

在 `finance-data` 目录执行：

```powershell
uv sync --default-index https://pypi.tuna.tsinghua.edu.cn/simple
uv run init_db.py
uv run -m generate.main --profile full   # 小数据量用 --profile smoke
uv run -m app.main
```

启动后验证：

- Swagger UI：`http://127.0.0.1:8000/docs`
- OpenAPI JSON：`http://127.0.0.1:8000/openapi.json`

> `init_db.py` 会先查同名库，存在就 **DROP 再重建**，然后导入 `sql/finance.sql`（见 `init_db.py` 的 `delete_db` / `create_db`）。库里已有数据时不要随手执行。

## 3. 数据库

### 3.1 客服库

客服的表由服务启动时自动创建（`assistant/utils/db.py` 的 `create_tables`），只需要先建库：

```sql
CREATE DATABASE IF NOT EXISTS finance_assistant DEFAULT CHARSET utf8mb4;
```

启动后自动出现两张表：

| 表 | 用途 |
| --- | --- |
| `dialogue_states` | 按 `sender_id` 保存完整对话状态 JSON（`sender_id` 主键 + `state_json`） |
| `faq_items` | 知识检索用 FAQ，初始为空，按 [04](04-知识检索与Prompt.md) 写入数据 |

新增金融槽位不需要改表结构——整段会话状态都在 `state_json` 里。

### 3.2 统一 MySQL（密码/端口）

中台与客服默认密码不同：中台 `.env` 的 `DB_PASSWORD` 默认 `123321`，客服 `DATABASE_URL` 常写成 `123456`。**两个方案二选一，不要同时占用同一个端口起两个 MySQL。**

方案 A（推荐）：复用中台的 MySQL。

1. 用 `docker/docker-compose.yaml` 启动 MySQL（root 密码 `123321`）；
2. 客服 `.env` 的 `DATABASE_URL` 改成：

```text
DATABASE_URL=mysql+aiomysql://root:123321@127.0.0.1:3306/finance_assistant?charset=utf8mb4
```

3. 在同一实例里创建 `finance_assistant` 库。

方案 B：复用本机已有 MySQL。

1. 本机密码以实际为准（例如 `123456`）；
2. 改中台 `.env` 的 `DB_PASSWORD=123456`；
3. 重新执行 `init_db.py` 与 `generate.main`。

> 固定一个实例、把两边配置改成一致，比迁移数据省事。

## 4. 客服 `.env` 全量配置

`.env` 必须放在 `finance-assistant/` 根目录（`conf/config.py` 用 `Path(__file__).parents[2] / '.env'` 定位）。

```ini
LLM_MODEL=qwen-flash
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=sk-xxxx

FINANCE_API_BASE_URL=http://127.0.0.1:8000
FINANCE_CHANNEL_CODE=MOBILE_BANK
FINANCE_OPERATOR_NO=EMP000001
DEMO_CUSTOMER_NO=CUS00000001
FINANCE_RAG_BASE_URL=

DATABASE_URL=mysql+aiomysql://root:123321@127.0.0.1:3306/finance_assistant?charset=utf8mb4

APP_HOST=0.0.0.0
APP_PORT=18083
```

| 变量 | 说明 |
| --- | --- |
| `LLM_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY` | 意图识别与回复润色使用的大模型 |
| `FINANCE_API_BASE_URL` | 中台地址，代码自动拼 `/api/v1` |
| `FINANCE_CHANNEL_CODE` | 作为 `X-Channel-Code` 发送，必须是 `dim_channel` 中存在且启用的值，否则 `403 CHANNEL_NOT_AVAILABLE` |
| `FINANCE_OPERATOR_NO` | 作为 `X-Operator-No` 发送，必须是 `dim_employee` 中存在且启用的值，否则 `403 EMPLOYEE_NOT_AVAILABLE` |
| `DEMO_CUSTOMER_NO` | 演示客户号，同时作为 `Authorization: Bearer <customer_no>`；对话里 `customer_no` 为空时回落到它 |
| `FINANCE_RAG_BASE_URL` | 外部知识库检索地址，留空则跳过 RAG |
| `DATABASE_URL` | 客服自己的库，与中台库相互独立 |
| `APP_HOST` / `APP_PORT` | 客服监听地址，默认 18083 |

中台 `finance-data/.env` 的变量为 `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` / `APP_PORT`。

## 5. 选择演示身份

金融接口鉴权不是账号密码，而是三个请求头：

- `Authorization: Bearer <customer_no>`：客户登录态
- `X-Channel-Code`：渠道编码，必须存在于 `dim_channel`
- `X-Operator-No`：员工编号，工单类接口需要，必须存在于 `dim_employee`

### 5.1 找演示客户

优先选一个「有账户 + 有交易 + 有有效授信额度」的客户：

```sql
SELECT
    c.customer_no,
    a.account_no,
    cl.limit_no,
    cl.available_limit_amount
FROM customer c
JOIN bank_account a ON a.customer_id = c.id
JOIN credit_limit cl ON cl.customer_id = c.id AND cl.limit_status = 'active'
WHERE c.customer_status = 'active'
LIMIT 5;
```

没有结果时：换客户、调 `generate` 的 profile 重新生成，或先只演示账户/交易/工单。

> 客户号形如 `CUS00000001`（`code("CUS", customer_id, 8)`，见 `generate/layers/layer2.py`），账户号 `ACC...`，授信额度号 `CL...`，贷款申请号 `LAP...`，工单号 `TKT...`。

### 5.2 找渠道和员工

```sql
SELECT channel_code FROM dim_channel WHERE channel_status = 'active' AND yn = 1 LIMIT 5;
SELECT employee_no FROM dim_employee WHERE employee_status = 'active' LIMIT 5;
```

把结果填入 `FINANCE_CHANNEL_CODE`、`FINANCE_OPERATOR_NO`。

### 5.3 账户状态坑

数据生成器把正常账户写成 `normal`，而审批建合同、交易类接口只认 `active`。若审批贷款报「客户缺少可用还款账户」，执行：

```sql
UPDATE bank_account SET account_status = 'active' WHERE account_status = 'normal';
```

每次重新初始化数据后需要重跑一次。详见 [06-Docker部署与启动.md](06-Docker部署与启动.md) 第 7.1 节。

## 6. 启动客服

```bash
# 1) 先启动金融中台（8000）
cd finance-data
uv run -m app.main

# 2) 再启动客服
cd finance-assistant
uv sync
python main.py
```

启动入口是根目录 `main.py`：

1. `init_dialogue_engine()`：加载 `flow_config/user_flows.yml`、注册 6 个 Action、装配 7 个知识 Provider；
2. `uvicorn` 拉起 `assistant.api.app:app`；
3. FastAPI `lifespan` 中依次执行：创建数据库引擎 → 建表 → 创建 HTTP 客户端；关闭时释放连接。

> 请用 `python main.py` 启动。直接执行 `uvicorn assistant.api.app:app` 会跳过 `init_dialogue_engine()`，请求时报对话引擎未初始化。

启动成功判断：

- 控制台输出 `Uvicorn running on http://0.0.0.0:18083`；
- `http://127.0.0.1:18083/docs` 能看到 `/api/chat`、`/api/chat/history`；
- MySQL 未启动会在启动阶段直接抛连接错误，此时先修数据库而不是改代码。

## 7. 与中台的调用约定

- 每个请求自动带 `Authorization: Bearer <customer_no>`、`X-Channel-Code`、`X-Request-Id`；工单类额外带 `X-Operator-No`。
- 中台成功时 `code=0`；失败时 `code` 是**字符串**错误码且 HTTP 为 4xx。判断逻辑要写成 `resp.status_code >= 400 or payload.get("code") != 0`。
- 写接口另有 `request_no` 做幂等，和 `X-Request-Id` 不是一回事：`request_no` 首次生成后写回槽位，重试复用。
- `assistant/utils/finance_client.py` 把常见错误码翻译成中文提示，未知错误回落到接口 `message`；金额统一 `Decimal` + 千分位两位小数。

## 8. 对外接口

### 8.1 发送消息 `POST /api/chat`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sender_id` | string | 是 | 用户标识，同时是会话状态主键 |
| `text` | string | 否 | 文本消息；与 `object` 二选一 |
| `object` | object | 否 | 对象消息，见 [03](03-Action与对象消息.md) |
| `message_id` | string | 否 | 不传则服务端生成 UUID |
| `customer_no` | string | 否 | 客户号；也可用 `X-Customer-No` 头传（头优先） |

文本请求：

```bash
curl -X POST http://127.0.0.1:18083/api/chat \
  -H "Content-Type: application/json" \
  -d '{"sender_id":"u1001","text":"帮我查一下我的账户余额"}'
```

对象消息请求（用户点了账户卡片）：

```bash
curl -X POST http://127.0.0.1:18083/api/chat \
  -H "Content-Type: application/json" \
  -d '{"sender_id":"u1001","object":{"type":"account","id":"6222020200000001","title":"储蓄卡","attributes":{}}}'
```

响应：

```json
{
  "sender_id": "u1001",
  "message_id": "9f0c...",
  "messages": [{"text": "你好，这里是金融智能助手……", "object": null}]
}
```

`messages` 是列表，一轮可能返回多条（例如先说明再给结果）。

### 8.2 查询历史 `GET /api/chat/history`

```bash
curl "http://127.0.0.1:18083/api/chat/history?sender_id=u1001"
```

返回该用户全部会话中的所有轮次，`role` 为 `user` 或 `bot`。

PowerShell 调用时注意编码（避免中文乱码、避免反斜杠被吞）：

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8
$body = @{ sender_id = "u1001"; text = "你好" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:18083/api/chat" -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

## 9. 连通性自检

先直接打中台，确认契约和鉴权都没问题。

### 9.1 查账户列表

```powershell
$h = @{
  Authorization    = "Bearer CUS00000001"
  "X-Channel-Code" = "MOBILE_BANK"
  "X-Request-Id"   = [guid]::NewGuid().ToString()
}
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/customers/CUS00000001/accounts" -Headers $h
```

期望 `code = 0`，`data.list[]` 中每项含 `account_no`、`balance_amount`、`currency_code`、`account_product {product_code, product_name}`。

### 9.2 查授信额度

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/customers/CUS00000001/credit-limits" -Headers $h
```

期望 `data.list` 中至少有 `limit_no`、`available_limit_amount`、`product_code`。

> 该接口返回客户名下**全部**额度，不返回 `limit_status`。多条时优先选 `available_limit_amount` 最大的一条；额度是否可用由 `POST /loan/applications` 内部校验 `limit_status == 'active'`。

### 9.3 创建工单

```powershell
$h["X-Operator-No"] = "EMP000001"
$body = @{
  request_no     = [guid]::NewGuid().ToString()
  customer_no    = "CUS00000001"
  ticket_type    = "complaint"
  ticket_title   = "转账未到账"
  ticket_content = "交易号 TX...，转账一直未到账"
  related_type   = "none"
} | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/support/tickets" `
  -Method Post -Headers $h -ContentType "application/json" -Body $body
```

期望返回 `data.ticket_no`。

## 10. 常见错误对照

| 错误 | 原因 | 处理 |
| --- | --- | --- |
| `401 MISSING_AUTHORIZATION` / `401 MISSING_HEADER` | 缺 `Authorization` 或 `X-Channel-Code` | 两个头都带上 |
| `401 INVALID_AUTHORIZATION` | 不是 `Bearer ` 前缀 | 使用 `Bearer <customer_no>` |
| `401 PRINCIPAL_NOT_FOUND` | token 既不是客户号也不是员工号 | 用库里真实的 `customer_no` |
| `403 CUSTOMER_SCOPE_FORBIDDEN` | 请求体客户号与登录客户号不一致 | 演示阶段固定同一个客户 |
| `403 EMPLOYEE_NOT_AVAILABLE` | 工单接口没有有效 `X-Operator-No` | 从 `dim_employee` 取真实员工编号 |
| `403 CHANNEL_NOT_AVAILABLE` | `X-Channel-Code` 不存在或未启用 | 从 `dim_channel` 取真实渠道 |
| `404 CUSTOMER_NOT_FOUND` | `DEMO_CUSTOMER_NO` 不在库里 | 重新查客户号 |
| `409 CREDIT_LIMIT_NOT_ENOUGH` | 申请金额超过可用额度 | 降低金额或换客户 |
| `409 CREDIT_LIMIT_STATUS_FORBIDDEN` | 额度不是 `active` | 换一条有效额度 |
| `400 LOAN_AMOUNT_OUT_OF_RANGE` | 金额不在产品区间 | 用产品详情的 `min_amount/max_amount` |
| `400 LOAN_TERM_OUT_OF_RANGE` | 期限不在产品区间 | 用产品详情的 `min/max_term_months` |
| `404 ACCOUNT_NOT_FOUND` | 账户号不存在或不属于当前客户 | 用客户账户列表接口先查 |
| `Access denied for user 'root'` | MySQL 密码不一致 | 统一 `.env` 中的密码 |
| `Can't connect to MySQL server` | 端口冲突或容器没启动 | 只保留一个 3306 实例 |
| 启动报 `dialogue engine` 未初始化 | 用 `uvicorn assistant.api.app:app` 启动 | 改用 `python main.py` |
| 大模型 401 / 超时 | `LLM_API_KEY` 无效或网络不通 | 换 key；确认能访问 `LLM_BASE_URL` |
